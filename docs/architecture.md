# 実装の詳細

[README](../README.md)

x86-64の小さな自作OSです。Dで実装したUEFIローダーがカーネルを起動します。カーネル本体に加え、ディスク・入出力ドライバ、ファイルシステム、シェル、GUI、ユーザープログラムもDで実装しています。CPUのモード切り替えや割り込みの入口にはDのインラインアセンブリを使い、ローダーとカーネルはLDCの `-betterC` でビルドします。

## 起動と各モジュール

- `boot/loader.d` は起動元のESPから `kernel.elf` を読み込み、GOPの画面情報とメモリマップを取得します。続いて `boot/boot_paging.d` でページテーブルを作成し、UEFIのブートサービスを終了して `source/boot_info.d` の起動情報をカーネルへ渡します。
- `source/kernel.d` は起動情報を受け取り、ディスクをマウントしてシリアルとGUIのポーリングを始めます。
- `source/pci.d` がPCI機器を列挙し、`source/ata.d` がIDEの両チャネル・両ドライブを `IDENTIFY` で検査します。`source/storage.d` と `source/block_device.d` を通じて、ファイルシステムに容量とブロックI/Oを渡します。
- `source/filesystem.d` は各ファイルを2世代分保持します。保存時は古い世代側に本文をセクタ単位で書き込み、最後にチェックサムを含むメタデータを書き込みます。起動時は有効な世代のうち新しい方を選びます。なお、ブート用の仮想FATは読み取り専用であり、データ用のDlangFSとは別です。
- `source/app_registry.d` は同梱アプリの起動先、ウィンドウ配置、多重起動上限、起動キー、文書担当を定義します。`source/desktop.d` はデスクトップ、タスクバー、ウィンドウの前後関係を管理します。`source/ps2.d` はキーボードとマウス、`source/shell.d` はシリアルシェルを担当します。
- `source/graphics.d` は解像度に合わせて確保したRAM上に画面を合成し、完成した画素データをUEFIから引き継いだフレームバッファへ転送します。カーソルやウィンドウの移動、およびCounterの定期更新では、影響を受ける範囲だけを転送します。
- `source/privilege.d` はGDT、TSS、IDTを設定してRing 3へ切り替えます。各プロセスは独立したページテーブルとユーザースタックを持ち、組み込みの実行コードを読み取り専用で共有します。
- `source/process.d` は最大15プロセスをラウンドロビンで実行します。同時に開けるウィンドウは7枚までです。システムコールには `INT 0x80` を使い、ユーザープロセスが処理を譲らない場合はローカルAPICのタイマーで実行を中断します。
- `source/gui.d` はデスクトップから起動したアプリに入力を届け、アプリから受け取った描画命令を検証してウィンドウの内側に合成します。

Counterは `apps/counter/` から、Files、Editor、Calc、Game、Monitorは `apps/builtin/` からELFにビルドし、DlangFSに配置します。デスクトップのランチャーはディスク上のELFを読み込み、それぞれを独立したRing 3プロセスとして起動します。ランチャーからは全アプリを同じ手順で起動します。`apps/experiments/` のサンプルをビルドして実行する手順とABIは [apps/README.md](../apps/README.md) にあります。

シェルから起動した未登録のELFも `guiCreate` でウィンドウを作成でき、タイトルはアプリ側で指定します。起動時に `desktop.apps` があれば登録内容を置き換えます。形式と追加手順は [docs/desktop-apps.md](desktop-apps.md) を参照してください。保存前の編集内容はゲストメモリにあります。実機での起動は未検証です。

標準druntime用の静的ELFでは、`PT_TLS` から主スレッドのTLSを作ります。初期値をコピーして残りをゼロ化した専用領域と、`FS:0` の自己ポインタを用意します。プロセス切り替え時に `IA32_FS_BASE` を設定し、カーネルへ戻った後は `0` に戻します。詳細は [druntimeの移植](druntime.md) を参照してください。

## デスクトップの時計

タスクバーの右側にRTCの日付と時刻を表示し、毎秒更新します。起動時にUEFIの `GetTime` で読み取り、取得時のTSCとともに渡して、その後の経過時間を加算します。RTCやファームウェアの設定自体は変更しません。取得に失敗した場合や暦の値が不正な場合は、`RTC unavailable` と表示します。

表示する日時はファームウェアから得た値そのものであり、タイムゾーン変換、夏時間補正、NTP同期、サスペンド復帰時の再同期には未対応です。QEMUの既定はUTCで、日本時間への自動変換は行いません。RTCアクセスはUEFIが担当するため、CMOSの世紀レジスタが固定アドレスにあるとは仮定しません。実機での動作は未検証です。

## 時刻源

`source/clock.d` は起動時にPCのPITチャネル2でTSCを校正し、GUIへ起動後の経過時間（ミリ秒）を渡します。画面の定期更新は50 ms、Snakeの進行は150 msです。APICタイマーも同様に校正し、ユーザープロセスの実行枠を約5 msに設定します。

ATA・PS/2のポーリング待機期限は100 msです。PITの初期校正だけは時刻源がまだないため、試行回数で待機を打ち切ります。校正に失敗した場合は起動を停止します。現在は単一CPUと一定周波数のTSCを前提としており、実機や複数CPUでの時刻精度は未検証です。

## 物理メモリの管理

UEFIローダーは最終メモリマップから空きRAMの範囲を渡します。`source/physical_memory.d` はその領域を4 KiBページとして管理し、プロセス起動時にページテーブル、コード、スタック、ヒープを確保します。ページは割り当て時にゼロ化し、終了、kill、例外、ELF読み込み失敗時に回収します。`mem` の `Free pages` が現在の空き容量です。

ファームウェアやローダーが予約した領域は回収しません。管理できる空き領域は最大128範囲で、超過時は起動を拒否します。ページテーブルは必要な枝だけを作り、ELFは256 MiB未満のロード用領域へ配置します。ヒープは初期64 KiBからシステムコールで拡張・縮小でき、失敗時は元の内容を保持します。詳しい仮想アドレス配置とAPIは [アプリ開発](../apps/README.md) を参照してください。

## 待機とアイドル

GUIアプリは `guiWait` を使い、入力、フォーカス変更、ディスク状態変更、指定期限のいずれかを待ちます。待機中はスケジューラがユーザーコードを実行しません。Counterの一時停止中、EditorやCalcの入力待ち、停止中のGameは無期限に待機し、動作中のCounter、Game、Monitorは更新期限を指定します。一般のアプリ向けにミリ秒単位の `sleep` も用意しています。

実行可能なプロセスもシリアル入力処理もない場合、CPUは `HLT` で待機します。シリアル受信はIRQ4でリングバッファへ取り込むため、アイドル中も受信時に復帰します。一方、PS/2入力はまだポーリング式のため、約1 msごとにAPICタイマーでも復帰します。ATAのI/Oは同期式のままです。

ウィンドウの終了通知から強制終了までには1秒の猶予を設けています。未保存状態であれば強制終了を予約せず、通知後に未保存状態が届いた場合も予約を取り消します。保存済みの状態で改めて閉じる操作をすると、新しい猶予を開始します。

## ディスクの配置と容量

DlangFS4の標準仕様は16ファイル・1ファイル1 MiBです。配置と容量はチェックサム付きのディスクヘッダから読み取ります。`python3 tools/format-disk.py build/small.img --slots 8 --file-bytes 8192` のように小さい容量のディスクも作れます。マウント後の上限は `fsinfo` で確認できます。現在のビルドが対応する上限を超えるイメージや不正なヘッダを持つディスクは、書き込まずに拒否します。詳細は [ディスク形式](dlangfs.md) を参照してください。

大きなELFを保持するため、ファイルキャッシュには16スロットで約16 MiB、読み込み用とシェル転送用に各1 MiBを静的に確保しています。GUIの文書バッファは16 KiBです。

## ストレージの検出範囲

データディスクはPCI IDEのprimary/secondary、master/slaveのどこに置いても検出します。互換モードでは仕様で定められたポート、nativeモードではI/O BARを使います。`IDENTIFY` でLBA対応、512バイト論理セクタ、`FLUSH CACHE` 対応、および容量を確認します。現在の転送方式は同期ATA PIOのLBA28で、AHCI、NVMe、USB、パーティション表には未対応です。QEMUでは互換モードの4つの接続位置を検証済みですが、nativeモードと実機は未検証です。

他の形式のディスクは先頭セクタを読み取って判別し、DlangFS4の候補が1台だけの場合にマウントします。DlangFS4の候補が複数ある場合は、書き込まずに拒否します。検出できるATAディスクは最大32台で、超過時もマウントしません。
