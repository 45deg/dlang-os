# デスクトップアプリの登録

DlangFSに `desktop.apps` を配置すると、次回起動時からランチャーの登録を置き換えられます。カーネルの再ビルドは不要です。設定がない場合は同梱6アプリの既定設定を使います。ELF自体は別途ディスクに配置する必要があり、設定ファイルもDlangFSのファイル枠を1つ使います。

例として、別のELF `example.elf` とEditorを登録する設定を示します。

```text
DLANGAPPS1
Example|example.elf|generic|80|60|300|180|1|F8|-
Writer|editor.elf|editor|220|90|468|340|4|F9|document
```

各行は `|` で区切った次の10項目で構成します。空白の自動除去や引用符によるエスケープは行いません。

| 項目 | 内容 |
| --- | --- |
| 表示名 | 印字可能ASCII、1〜24文字 |
| ELF名 | DlangFSのファイル名、1〜24文字。重複不可 |
| アイコン | `files`、`editor`、`counter`、`calc`、`game`、`monitor`、`generic` |
| x | -2048〜2048。負数は画面右端からの位置 |
| y | 0〜2048 |
| 幅 | 128〜768ピクセル。ウィンドウ枠を含む |
| 高さ | 80〜520ピクセル。ウィンドウ枠を含む |
| 同時起動数 | 0〜7。0は全体のウィンドウ上限まで、1は既存のウィンドウを前面に戻す |
| 起動キー | `-`、`F5`、`F8`、`F9`。キーの重複不可 |
| 文書担当 | `-` または `document`。文書担当は最大1アプリ |

アイコンは見た目だけを指定します。文書担当に指定したアプリはFilesからの文書を開く要求やF2の新規文書を受け取るため、対象ELFがGUIの文書イベントに対応している必要があります。文書担当がない場合、文書を開く操作はエラー表示になります。

配置は登録順で行われ、ウィンドウが重なる場合は右へ24ピクセル、下へ29ピクセルずらします。画面端では位置を調整します。登録できるのは1〜12件で、設定全体の上限は4096バイトです。改行コードはLFとCRLFの両方に対応し、空行、行頭 `#` のコメント、最終改行なしも受け付けます。先頭の有効行は `DLANGAPPS1` である必要があります。

設定の保存には、シリアルシェルの `put desktop.apps バイト数`、またはホスト側の `tools/install-apps.py --app /path/to/desktop.apps` を使います。ただし、インストーラは既存のファイルを上書きしないため、更新時は `put` を使ってください。

設定は起動時に専用メモリへコピーします。起動後の編集や削除は次回起動で反映されます。不正な形式、上限超過、重複した登録がある場合は設定全体を拒否して既定設定へ戻し、画面にエラーを表示します。部分的な適用や設定ファイルへの書き戻しは行いません。問題がある場合はシリアルシェルから修正・削除して再起動してください。

ランチャーに登録しないGUIアプリも、`run NAME &` と `guiCreate` を使ってウィンドウを作成できます。この場合は共通の既定サイズを使います。
